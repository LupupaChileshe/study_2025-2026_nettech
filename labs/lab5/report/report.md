# Цель работы

Построение простейших моделей сети на базе коммутатора и маршрутизаторов FRR и VyOS в GNS3, анализ трафика посредством Wireshark.

# Выполнение работы

## Моделирование простейшей сети в GNS3

1. Запущены GNS3 VM и среда GNS3, создан новый проект для моделирования сети.
2. В рабочей области размещены устройства: Ethernet-коммутатор и два оконечных узла VPCS.
3. Выполнено переименование устройств: рабочие станции получили имена PC1-chileshe и PC2-chileshe, коммутатор — msk-chileshe-sw-01.
4. Оконечные устройства соединены с коммутатором, включено отображение интерфейсов соединений.

   ![Топология простейшей сети в GNS3](01.png){ #fig:001 width=80% }

5. На узле PC1-chileshe открыт терминал VPCS и изучен список доступных команд с помощью справки.

   ![Просмотр справки команд VPCS](02.png){ #fig:002 width=80% }

6. Для узла PC1-chileshe задан IP-адрес 192.168.1.11/24 с указанием шлюза 192.168.1.1. Конфигурация сохранена в файл запуска.

   ![Задание IP-адреса PC1 и сохранение конфигурации](03.png){ #fig:003 width=80% }

7. Аналогичным образом для узла PC2-chileshe задан IP-адрес 192.168.1.12/24, после чего конфигурация также была сохранена.
8. Проверена связность между узлами с помощью команды ping. Получены ответы без потерь, что подтверждает корректность настройки сети.

   ![Проверка соединения между PC2 и PC1](04.png){ #fig:004 width=80% }

## Анализ трафика в Wireshark

1. На соединении между PC1-chileshe и коммутатором запущен захват трафика с помощью Wireshark.
2. После запуска всех узлов в проекте в окне анализатора зафиксированы ARP-сообщения, включая gratuitous ARP-запросы.
3. Установлено, что ARP используется для определения MAC-адресов узлов в локальной сети, а gratuitous ARP применяется для уведомления сети о соответствии IP- и MAC-адреса.

   ![Анализ ARP-сообщений в Wireshark](05.png){ #fig:005 width=80% }

4. В терминале PC1-chileshe изучены параметры команды ping, поддерживающей работу в ICMP, UDP и TCP режимах.

   ![Просмотр опций команды ping](06.png){ #fig:006 width=80% }

5. Выполнен одиночный эхо-запрос в ICMP-моде к узлу PC2-chileshe.
6. В Wireshark зафиксированы пакеты ICMP Echo Request и ICMP Echo Reply, подтверждающие успешный обмен сообщениями на сетевом уровне.

   ![ICMP Echo-запрос и ответ](07.png){ #fig:007 width=80% }

7. С узла PC1-chileshe выполнен одиночный эхо-запрос в UDP-моде.
8. В анализаторе трафика зафиксирован UDP-пакет, инкапсулирующий эхо-данные, что демонстрирует передачу без установления соединения.
9. Отмечено отсутствие механизмов подтверждения доставки на транспортном уровне.

   ![Передача эхо-запроса в UDP-моде](08.png){ #fig:008 width=80% }

10. Выполнен одиночный эхо-запрос в TCP-моде между узлами сети.
11. В Wireshark зафиксирован процесс установления соединения (SYN, SYN-ACK, ACK), передача данных и корректное завершение соединения.
12. Установлено, что TCP обеспечивает надёжную доставку данных за счёт подтверждений и управления соединением.

   ![TCP-сессия при выполнении эхо-запроса](09.png){ #fig:009 width=80% }

# Вывод

В ходе работы были смоделированы простейшие локальные сети в среде GNS3 с использованием Ethernet-коммутатора, а также маршрутизаторов FRR и VyOS. Выполнена настройка IP-адресации оконечных устройств и сетевых интерфейсов маршрутизаторов, после чего подтверждена корректная связность между узлами сети. С помощью Wireshark проанализирован сетевой трафик, установлена роль ARP в разрешении MAC-адресов и особенности передачи ICMP-сообщений. Полученные результаты подтверждают корректность построенной топологии и работоспособность сетевых протоколов на канальном и сетевом уровнях.
